# Overall User Experience Changes

> Latest Interview with Falih | November 21st, 2026

## What Is This?

This is a note from my latest interview with Falih after showing the latest state of the prototype. The note is split into the renewal steps in the prototype. The note basically contains what Falih said would improve the app to simplify the workflow so we can have a more stable MVP (minimum viable product).

## Important

We should have the "tour" feature again for first time users. This feature should be reaccessible again and again under the user menu (right below case list).

---

## 1. Renewal Materials

### QS Overview

- **Falih's Quote:** I want AI to play a more significant role here. I want the *"First Things First"* to be: AI Check the previous period's Final Slip (or Cover Note) against the latest Standard T&C that the Insurance Broker already have.
   - **Desired Outcome:** AI can flag the difference between the Final Slip/Cover Note (from the previous period) vs the Standard T&C, then the human user can simply decide whether to take the clause from the T&C and put it into the Quotation Slip (QS).
- **Irfan's Interpretation**: I think we could add more features:
   - A way to store the latest T&C that the broker has (with version control), like a single living document that the app can refer to every time we want to check against the T&C.
   - A **Superadmin** role per company that manages user roles and privileges (brokers and clients). This superadmin should (by default) have the ability to update Standard T&C. The Standard T&C privilege could also be given to other users assigned by the Superadmin.

### Wording

- **Falih's Quote:** I think the "Wording" part in step 1 is not strictly necessary at this point. Becuase we already have a standard set of words to use inside our Standard T&C. This could go in the "Standard T&C" settings so we don't have to check wording again.

### Terms & premium

- **Falih's Quotes:**
   - The Final Slip should state any discounts, but we can still remove this from the QS (still go with the gross premium). Insurers don't really have to know how much discount the broker is giving to the client. For property all risk (PAR), 15% discount to the client is imperative.
   - Because we normally use Excel, I think it's good if we can upload the Excel file, then it could be embedded inside the Quotation Slip Word file beautifully.
   - It would be super helpful if the AI can match the Excel file (addresses, occupancy, rate) with OJK rules (See: https://ojk.go.id/id/kanal/iknb/regulasi/asuransi/surat-edaran-ojk/Documents/SAL%20-%20Lampiran%20I%20-%20Property%20Amandemen.pdf)
- **Irfan's Interpretation:**
   - Maybe the app can have a standard Excel template the broker can download, then upload it again with their data. OR, AI can handle that Excel scanning and have a pop-up window so the human user can confirm before going forward.
   - The **Desired Outcome:** Human users (broker) can download the final Quotation Slip (Word file) and immediately send it to the insurer.

## 2. Insurer Review

- **Falih's Quotes:**
   - Usually, when we send QS to the insurers, they would return to us with an annotated PDF of the QS (maybe they scratch a few clauses here and there, provide notes, etc.). It would be great if the app had an OCR and can detect the revisions provided by the insurer. If this is the case, we need to integrate email into this app's workflow so we can communicate back-and-forth with the insurer with Rekonvia staying in the loop.
   - Or, if they agree with our QS, they can simply approve it via email. We need a way to feed this agreement into the app so we can move forward.
- **Irfan's Notes:**
   - For this demo, let me know if we can integrate some kind of email system into this app. Recommend me something that can be incorporated easily into this app. Ask me questions if needed.

## 3. Client Proposal

- **Falih's Quotes:**
   - The current client side of the app is great. It's very simple, they can review our proposal (PDF), see the Excel file containing the list.
   - The clients should have a way to give us notes regarding the proposal so we can change them.
   - This rarely happen, but some clients can make us go back-and-forth with them regarding the contents of the proposal. Let's say one of their buildings' sum insured is changed, this will automatically adjust the premium. If the premium goes up, clients would likely ask for more discount.
   - We the brokers usually retain the current discount, per OJK rules. But it would be useful to have some sort of an optional step to finalize the premiums and discounts with the client, should they get nosy about this.

## 4. Data Reconciliation

- **Falih's Quotes:**
   - I'm not sure if this step is strictly necessary, because if the client already approve, the data should be good.
   - **Irfan's Interpretation:** I assume since AI already done most of the checks in step 1.
   - So maybe this "Data Reconciliation" step could be used just to see a recap of what was updated for/from the client.
   - I think we can merge this step with "5. Final Review + Binding". But to be safe, maybe at this point, we can re-confirm the new property value, its' sum insured, and the adjusted premium.
   - During final review, I think there shouldn't be more manual reviews by the human users. Clients mostly only care about premiums, they rarely pay attention to the clauses.
   - So, the step up from Proposal to Draft Final Slip (DFS) most likely will contain the same clauses, only differs in the premium.
   - When binding the final Word file, in the last page, there should be room for broker remarks and the signature from the insurer.
